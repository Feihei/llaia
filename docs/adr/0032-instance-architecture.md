# ADR-0032: 实例化架构——任务线即实例，serve 退化为宿主

- 状态：Accepted（设计定案 2026-09-23，待实现）
- 日期：2026-09-23
- 关联：修订 [ADR-0031](0031-task-session-model.md)（推翻「明确不做：并行双任务线」「全局单活跃」两条）；[ADR-0002](0002-agent-architecture.md)（主控 Agent 定位）；[ADR-0022](0022-ask-user-suspend-resume.md)（ask_user 挂起）；[ADR-0025](0025-system-prompt-memory-budget.md)（MEMORY trim，缓存需 per-instance 化）

## 背景 / Context

并行能力讨论（2026-09-23）中暴露出三层机制的概念冗余：

1. **delegate 子 agent**（worker）：无人格、fresh context、借工具集、结果摘要回传即消亡；
2. **session 任务线**（ADR-0031，context 分页）：主 agent 人格延续、独立 sqlite 线、bound_path，但同一时刻全局只有一条活跃线；
3. **设想中的多进程实例**（runtime）：多个共用配置的主 agent 并行。

冗余感的根源：任务线已具备名字、bound_path、独立历史，天然往「任务单元」生长；多实例也在往「每实例一个任务」生长。若两者都长成任务，就是两套任务身份并存。曾评估「正交模型」（任务线永不获得执行能力、实例与线分立），被否决——该模型靠 ADR 纪律防守边界，而「任务做着做着想让它后台跑」的需求拉力迟早腐蚀纪律。

## 决策 / Decision

**身份合一：实例 = 任务线的运行时形态。** 一条任务线不再只是 sqlite 记录 + 内存 Context 分页，而是一个拥有独立 Agent 运行时的「实例」。并行发生在实例之间，每实例内部保持既有的单 agent 串行模型（`Arc<Mutex<Agent>>` 不拆）。

具体定案：

1. **serve = 宿主，不再是 agent**。宿主持有：频道连接、WebUI、实例注册表 / supervisor（生命周期、健康、重建）。所有 agent——包括 main——都是宿主管理的实例。频道连接挂宿主而非挂 agent，重建实例不影响频道连接。
2. **main 也是一个实例**（默认实例）。SOUL/USER 写入、first-run bootstrap、记忆压缩等「人格主权」操作归 main；其余实例是人格副本。
3. **频道串行附着**：IM/CLI 频道同一时刻附着一个实例，`/session <名>` 切线 = 换绑附着（**修订 ADR-0031 Q4「全局单活跃」→ per-channel 单活跃**，各频道各自持有附着指针）。并行入口只有 WebUI：多面板各自订阅一个实例。
4. **memory 分层**：实例的 memory 注入 = 主 MEMORY（走 `trim_memory_to_budget` 预算）拼接实例私有 MEMORY；`memory_write` 写当前实例私有 memory（main 写主 MEMORY）。读写分工消除共享写冲突。
5. **SOUL/USER 共享只读**，实例不写（bootstrap / profile 编辑只在 main 生效）。
6. **delegate 保留 worker 语义不动**，每实例可委派。worker 与实例的分界：worker 无人格、不可交互（不能 ask_user、不走审批对话）；实例有人格、可对话、可审批。
7. **执行载体 v1 = 进程内虚拟实例**：宿主进程内独立 Agent 状态 + 独立 Mutex，tokio 多任务并行。真进程升级（`LLAIA_HOME` per profile、独立 OS 进程）作为后续载体选项预留，接口按实例抽象设计、不锁死进程内实现。
8. **重启语义**：宿主重启只恢复 main 实例（对齐 ADR-0031「任务线不进隐式续接」）；任务实例不自动拉起，用户显式进入时按既有回灌通路（6000 字符预算）重建上下文。宿主重启 = 全实例重建（v1 虚拟实例的固有边界，真进程载体落地后才可能做到「重启 main 不动其他」）。

## 替代方案（均否决）

| 方案 | 否决理由 |
|---|---|
| 正交模型：任务线永不获得执行能力，实例与线分立 | 靠纪律防守边界，需求拉力（任务后台跑）迟早腐蚀；两套任务身份并存的冗余感正是本 ADR 要消灭的 |
| 主进程内并行：拆 `Arc<Mutex>`、history per-turn 快照 + 合并 | 单用户私人助理的主会话不需要并发；`/steer` 已覆盖「任务运行中插话」；深改造高风险零对价 |
| delegate 扩展承载一切（可交互会话也塞进 worker） | worker 的价值恰在不可交互（无人格、干完即走）；ask_user / 审批流无法向 worker 路由 |
| 多 OS 进程一步到位 | 单用户单机场景下虚拟实例已满足并行需求；进程管理（端口、监督、代理）复杂度先不背 |

## 影响面

- `commands/mod.rs::serve_cmd`：拆为宿主启动器 + 实例工厂；频道 spawn 改为「构造时拿注册表」而非「构造时绑定 agent」。
- 频道层（`Channel` trait 实现方）：持有实例注册表，消息到达按附着指针路由到实例；`/session` 切线 = 换绑。
- WebUI（`web.rs` + 前端）：新增 `/api/instances`（列表/状态）；WS 按实例 id 订阅，session rail 升级为 instance rail（主线置顶 + 活跃实例并行面板）。
- `agent/`：回合起点机制（bootstrap / reminder / envprobe / todo）内聚在 agent 内，实例化后自然随实例走，改动小。
- `memory/sqlite.rs`：sessions 表结构基本兼容（实例 = 现有 kind='task' 线 + 运行时状态）；WAL 多连接并发写可行，每实例独立连接。
- `init_system_meta` / `trim_memory_to_budget`：system prompt 因实例 MEMORY 拼接而不同，**缓存必须 per-instance 化**（现为全频道共享单份）。
- 审批流（`/ok` `/deny`）与 ask_user 挂起：审批 id / 问题 id 需带实例路由信息，频道答复时路由到正确实例。
- cron：保持 fork_for_isolated worker 语义，挂宿主全局执行（不 per-instance 分裂）。
- ADR-0031 修订：「明确不做：并行双任务线」与「全局单活跃」由本 ADR 替代；bound_path、回灌、归档语义全部沿用。

## 已识别风险（实现时逐项处置）

1. **本地单槽 provider 的并行瓶颈**：多实例并行打到同一本地模型（Ollama 单槽 / llama.cpp）会排队串行化，甚至上下文互相驱逐——并行收益归零。并行实例适配云端 API 多并发场景；本地模型用户实际上仍串行。属固有约束，文档说明即可，不做框架层限流。
2. **切线时 in-flight turn**：频道附着切换时旧实例正在跑的 turn，结果仍回传旧实例（不打断），新消息进新实例；频道侧需容忍「旧实例异步回执晚到」的乱序展示。
3. **共享副作用资源冲突**：两实例并行操作同一目录（git index.lock、同一构建目录）会互踩。约定并行实例 bound_dir 不重叠；框架不强制。
4. **通用事实晋升缺口**：任务实例学到的通用事实（用户偏好等）只进实例私有 memory，主 MEMORY 感知不到。v1 接受该缺口；后续可加「归档实例时 LLM 提炼通用事实写回主 MEMORY」。
5. **token 成本线性增长**：每实例独立上下文、独立压缩、独立 system prompt（MEMORY 各拼一份）。由并发数天然封顶（活跃实例数 = 用户显式开启数）。
6. **频道消息到达时实例 busy**：需要 per-instance 消息队列（现状全局串行天然不存在此问题）。

## 明确不做

- 真进程实例、跨机实例（接口预留，需求出现再立项）。
- 实例间消息互通 / 协作（实例彼此独立，协作经 main 转述或共享文件系统）。
- 主 MEMORY 共享写 / 分布式锁（读写分工已消除）。
- 自动实例生命周期（自动拉起/闲置回收）：显式进出，对齐任务线既有哲学。

## 未决

1. 实例私有 memory 的存储形态：文件（`workspace/instances/<name>/MEMORY.md`）还是 sqlite 列/表？倾向文件（与主 MEMORY 同构、可直接复用 trim 与 `/memory-compact`）。
2. 任务实例内 `file_edit` 写 SOUL.md/USER.md 的拦截粒度：目前靠 bootstrap 指令只注册在 main；实例化后需在工具层显式拒绝（防御深度）。
3. WebUI 并行面板的上限/退场交互（全部实例一页平铺 vs 可折叠）——前端实现时定。

## 修订（2026-09-23·同日）：实例生命周期三态、sessions.db 并发写、频道解绑语义

三个追加定案：

1. **实例生命周期三态**：`active`（有运行时）→ `dormant`（运行时释放、session 线留 sqlite、重进回灌无损重建）→ `archived`（显式 close，现有语义）。**退出是内存事件而非数据事件**——所有持久数据本就逐回合落 sqlite，运行时 Context 只是缓存，释放即"退出"、无损。显式 close 是唯一真退出；dormant 化可随时发生（回合中除外）。v1 不做自动闲置驱逐（实例内存开销 MB 级，不值得），留作后续优化。

2. **sessions.db 多实例并发写**：无实际竞争。WAL 模式天然支持多连接同库（一写多读、写锁排队），实施要求仅两条：每实例独立连接 + 每连接设 `busy_timeout`（5s 量级）。写入频率为 LLM 回合节奏的秒~分钟级小事务，非热路径。

3. **频道切线 = 解绑（detach）而非退出（修订上文「已识别风险」第 2 条）**：用户定案频道不并行、单附着，但切线时旧实例降级为 dormant 而非销毁——旧实例可能同时被 WebUI 订阅（手机 QQ 开任务、电脑 WebUI 并行看），频道侧切线不应殃及。~~切线立即生效，旧实例 in-flight 回合后台跑完、结果以通知回频道~~——**由同日修订 2 的 idle 检查取代**（见下）。由此**审批路由退化为平凡问题**：频道的审批恒属当前附着实例，其余实例的审批只出现在 WebUI——原「已识别风险」第 2 条（in-flight turn 乱序）与审批路由风险项的处置方案由此定案。

## 修订（2026-09-23·同日 2）：频道切线前置 idle 检查（取代上节第 3 条的「立即生效 + 后台完成通知」）

**动机**：上节原定「切线立即生效、旧实例 in-flight 回合后台跑完、ask_user/审批经通知通路送回频道」——重新审视为下策：IM 单窗口里两条线的问答交错（用户正与新实例对话，旧实例插话求审批）正是要避免的混乱；且 `/ok <id>` 需要跨实例路由，把刚消解的审批路由问题请了回来。

**定案：仅 idle 可切。** 切线命令执行前检查当前附着实例：

- 无 in-flight 回合 **且** 无未决 ask_user / 审批 → 放行，切换立即完成（旧实例 dormant 化）；
- 否则拒绝，提示具体等待项（「任务X 正在执行 / 等待回答 / 等待审批，处理完或 `/stop` 后再切」）。

**结构保证**：只有 in-flight 回合才可能新产生 ask_user/审批，idle 检查通过后不存在「切走后才冒出挂起项」的竞态——问题在结构上不存在，而非被机制善后。delegate 异步任务不受影响：实例转 idle 后切线，异步子任务完成走既有单向通知通路回频道（不需要用户应答，无交错）。原「切线立即生效 + 后台跑完通知」机制不再需要（delegate 异步通知保持不变）。

**兜底通路（全部既有机制）**：长任务中想问别的 → `/btw` 侧问或 WebUI 并行面板；任务卡住 → `/stop` 中止回合后再切；ask_user / 审批挂着 → 回答、`/ok` `/deny`，或 **`/cancel <id>` 放弃**（已存在于 `slash.rs`，question 与审批两类挂起一次覆盖，取消后不跑 continuation——文档命令清单需补记）。**已核实 `/stop` 不能中止 suspended 态**：ask_user 挂起时本轮 turn 已结束（`deferred` 即返回），`/stop` 只中断 in-flight 生成，空闲态下是 no-op——idle 检查因此必须显式查 ApprovalGate 非空，不能只查有无 in-flight turn（另：question 超时是惰性判定，仅在用户下一条消息到达时触发，无后台定时器，`timeout_secs=0` 永不超时）。
