# LLAIA v0.5.2

Patch release: QQ approval buttons land together with their fixes, plus a
delete guard for the terminal. One behavior change: destructive commands
inside the session bound path now move to `.trash/` instead of deleting —
opt out with `[tools.terminal] delete_guard = "off"`. Details in the git log.

## Features

- **Delete guard** — `rm` / `del` / `Remove-Item` inside the session bound
  path now move targets to `<workspace>/.trash/` (recoverable, no approval
  prompt) instead of silently deleting; outside the bound path it still
  requires approval. Set `delete_guard = "off"` to restore the old behavior.
- **QQ inline approval buttons** — tool-approval prompts carry ✅ / ❌ buttons
  instead of typing `/ok <id>` / `/deny <id>`; falls back to plain text if
  the platform rejects the keyboard.

## Bug fixes

- QQ button replies rejected with 40034025 "请求参数event_id无效" — replies
  now anchor to the dispatch event id, and approval resumption prefers the
  original message msg_id.
- QQ keyboards silently dropped on plain-text messages — prompts with buttons
  now send markdown (`msg_type=2`), as the platform requires.
- Generation Guard was blind to native reasoning streams — runaway thinking
  no longer burns the full 32k cap on every retry attempt.
- Degenerated reasoning is preserved (truncated head + total length, kept out
  of context) in the session store for forensics.
- powershell/cmd inline payloads now go through the T3 gate and require
  approval like `python -c` payloads.
