# LLAIA v0.5.1

Patch release on top of v0.5.0 — stability fixes plus a few small quality-of-life
features. No breaking changes, no config migration, nothing to do on upgrade.

## Bug fixes

- **Fresh-machine startup crash** — `llaia serve` / `chat` aborted with
  "the system cannot find the path specified (os error 3)" when `~/.llaia` did
  not exist yet (broken since the v0.2 migration logic landed; Windows
  `ERROR_PATH_NOT_FOUND` / Unix `ENOENT`). The migration step wrote its
  `.migrated_v0.2` marker before the config directory was created. Migration now
  creates the directory first, with a regression test pinning "bare `llaia serve`
  works on a brand-new machine".
- **Todo injection could resurrect finished work** — completed items were
  re-injected every turn with their `[x]` marks and ids. Weak models ignored the
  marks, read a stale all-done list as unfinished work, and "resumed" tasks from
  days earlier out of a bare greeting (2026-09-11 incident). Injection now
  carries only pending / in-progress items, injects nothing at all once
  everything is done (no id anchors to latch onto), and appends an id-free
  `(N of M already done)` line when partially done. Store, WebUI panel and
  explicit `todo list` output are unchanged.
- **Path validation hole for path-shaped program names** — the leading token of
  each command segment was treated as a program name and skipped entirely, so
  `/e/apps/blender.exe --version` bypassed every path check while the same path
  as an argument (`ls /e/apps/...`) required approval. Path-shaped leading
  tokens now go through validation; bare program names (`ls`, `git`) behave as
  before.

## Features

- **Trusted directories survive restarts** — directories approved via `/move`
  used to live only in the running process, so every serve restart cleared them
  and the same directory kept prompting for approval. They are now persisted to
  `<config_dir>/trusted_dirs.json`: loaded at startup with the agent home
  workspace seeded in (so home stays approved after `/move`), written back on
  every `/move` approval. Write failures degrade silently to session-level
  trust. This supersedes the "memory only, cleared on restart" note recorded
  under v0.4.0.
- **WebUI chat history replay** — opening chat now replays the current session
  line's tail (last 40 messages, including thinking and tool-call rows) when the
  pane is empty; switching lines backfills thinking and tool rows too. Approved
  tool results are persisted with a `[tool result: <name>]` prefix so session
  replay distinguishes them from real user messages (`/deny` and `/answer`
  already had markers, the approve path did not).
- **WeChat login QR in the WebUI** — the WeChat channel card on the Config page
  now renders the login QR itself (2.5s polling of
  `GET /api/channels/wechat/login`) instead of asking users to dig through the
  startup log or find `wechat_qr.png`. Saving with the channel enabled prompts
  for a restart (as before), after which the QR appears; the log print, the
  on-disk fallback, `wechat_state.json` re-login skipping and the `-14` re-scan
  logic are unchanged.
- **Inline approval buttons for the QQ channel** — tool-approval prompts now
  carry inline ✅ approve / ❌ reject buttons instead of requiring users to type
  `/ok <id>` or `/deny <id>` manually (painful on mobile, where copying the id
  is fiddly). Built on the QQ Bot callback keyboard: `group_id` mutual exclusion
  grays out the sibling button after one click, `permission` is locked to the
  channel owner's `openid` so others cannot act, and button clicks arrive as
  `INTERACTION_CREATE` events (intent `1<<26`) acked within 3s via
  `PUT /interactions/{id}`. The existing `ApprovalGate` / `resolve_approval`
  machinery is reused with zero agent-core changes. If the endpoint rejects the
  keyboard (codes 304062 / 40034029 / 40034127), the prompt falls back to a
  plain-text message identical to the old behavior.
