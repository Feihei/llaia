# P5: ask_user 阻塞式澄清 实现计划

> **For agentic workers:** REQUIRED SUB-SKILL: 使用 superpowers:executing-plans 按任务顺序实现。步骤用 checkbox (`- [ ]`) 标记追踪。

**Goal:** 提供 `ask_user` 工具：agent 在执行中主动向用户抛澄清问题并**阻塞等待**回答，再把答案作为工具返回值继续。复用 ADR-0020 的 ApprovalGate 挂起-回传机制；CLI 走 stdin 直问，无 stdin 频道走消息回传。

**Architecture:** `ask_user` 执行时注册 `PendingQuestion`（挂起本轮 turn，返回占位结果）；用户回答（CLI stdin 或 `/answer <id>` 消息）经 pending 注册表路由，触发 continuation turn 把答案写回上下文。与审批共用挂起-回传骨架，但 `PendingKind` 分 `Approval` / `Question`。

**Tech Stack:** Rust + tokio（oneshot/Notify 用于 CLI 直等；消息回传复用现有审批续跑）

**参考设计:** [ADR-0022](../adr/0022-ask-user-suspend-resume.md)，[ADR-0020](../adr/0020-permission-and-approval.md)

## Task 2: ask_user 工具实现

**Files:** Create `src/tools/ask_user.rs`, Modify `src/channels/cli.rs`（工具注册）

- [ ] 实现 `AskUser`：

```rust
pub struct AskUser { gate: Arc<ApprovalGate> }

#[async_trait]
impl Tool for AskUser {
    fn name(&self) -> &str { "ask_user" }
    fn description(&self) -> &str { "向用户提出一个澄清问题并阻塞等待回答；回答将作为本工具返回值。" }
    async fn execute(&self, args: &Value, channel: &str) -> Result<String> {
        let question = args.get("question").and_then(|v| v.as_str())
            .ok_or_else(|| anyhow::anyhow!("ask_user: missing 'question'"))?;
        let id = nanoid::nanoid!(8);
        self.gate.register_question(PendingQuestion {
            id: id.clone(), question: question.to_string(),
            channel: channel.to_string(), turn_id: current_turn_id(),
            created_at: now(),
        }).await;
        Ok(format!("⏳ 已向用户提问（id={}），等待回答", id))
    }
}
```

- [ ] 关键：返回占位后，**当前 turn 必须暂停**（不继续调模型），依赖 runner 已有的"pending 则暂停"逻辑（ADR-0020 Step 3）。需确认 runner 对 `ask_user` 的占位返回也能触发暂停（必要时在 runner 识别 `⏳ 等待` 或新增 `requires_suspend()` 标记）。
- [ ] 注册进工具集（条件 or 默认；建议默认注册，无副作用只读）。
