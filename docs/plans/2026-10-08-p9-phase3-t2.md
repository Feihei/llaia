# P9 Phase 3 · T2 受限进程落地（部署手册 + doctor 自检）

- 日期：2026-10-08
- 上位文档：[ADR-0033](../adr/0033-security-model.md)（L2 OS 最小权限）、[docs/plan.md](../plan.md) P9 Phase 3、[docs/guide/security-hardening.md](../guide/security-hardening.md)（T2 原始定案）
- 定案：2026-10-08 与 Feihei 确认走 **方案 A · 部署手册 + doctor 自检**（零新依赖）

## 背景与选型

Phase 3 目标：把 ADR-0033 L2 层（OS 最小权限，唯一不依赖命令形态的硬边界）从「文档规范」变成「可执行的落地物」。

三个候选形态（AskUserQuestion 评审）：

- **A · 部署手册 + doctor 自检**（选定）：security-hardening.md 扩成 T2 完整部署手册；`llaia doctor` 增加提权状态自检。零新依赖，terminal stdin 通路不动。
- B · A + 轻量 opt-in 包装：`runas /trustlevel:0x20000` 之类包装会断 `bash -s` 的 piped stdin（现有通路特意用它绕开 argv 转义），等于重做执行通路；且本机 os error 231 环境性问题使 terminal 侧改动难验证。弃。
- C · 原生 Windows 受限 token：需 windows-sys 新依赖 + CreateProcessAsUserW 手写管道，与轻量单 crate 定位冲突；且 Basic User token 对用户自身 profile 读写仍放行，防误删不防泄露。弃。

选 A 的结构性理由：T2 的原始定案（security-hardening.md 2026-09-07）就是「**整个 llaia 进程**以专用低权账户运行」——降权做在部署层比 per-command 包装更干净，代码侧只需提供可验证性（doctor），不需要执行通路。

## 交付物

### 1. `src/privilege.rs` — 提权状态探测（新模块，零依赖）

- `pub struct ElevationInfo { pub account: String, pub elevated: Option<bool> }`
- Windows：spawn `whoami` 取账户名；`whoami /groups /fo csv` 里 SID `S-1-16-12288`（High）/ `S-1-16-16384`（System）命中即 elevated=Some(true)，`S-1-16-8192`（Medium）即 Some(false)；探测失败 None。SID 字符串不随系统语言变化，输出解析可靠。
- Unix：spawn `id -un` / `id -u`，uid=="0" 即 elevated。
- 纯解析函数 `parse_windows_group_csv` / `parse_unix_id` 单测覆盖（whoami CSV 样例 + id 输出样例）。
- 探测失败静默降级为 None（doctor 显示 unknown，不报 error）。

### 2. `llaia doctor` 自检项

- CLI `doctor_cmd`：新增 `security:` 段——打印运行账户 + 提权状态 + T2 指引（指向 security-hardening.md）。
- 结构化 `doctor_checks`（WebUI `/api/doctor`）：新增 `security.privilege` 检查——
  - elevated=Some(true) → **warn**（"running with elevated privileges; prefer a dedicated low-privilege account per T2 (docs/guide/security-hardening.md)"）
  - elevated=Some(false) → ok（not elevated; for full T2 hardening see the deployment guide）
  - None → ok，detail 注明 unknown（probe failed）
- CLI 输出英文（项目约定）。

### 3. security-hardening.md 扩写为 T2 完整部署手册

- Windows：专用账户创建 → ACL 授予（config_dir / workspace 全控）+ 敏感目录默认拒绝确认 → 任务计划程序 / schtasks 服务化（不管登录与否都运行）→ `whoami /groups` 验证。
- Linux：`useradd -r` 系统账户 → systemd unit 加固（`User=`、`NoNewPrivileges=`、`ProtectSystem=strict`、`ProtectHome=`、`ReadWritePaths=`）→ 验证。
- 通用验证清单表格 + `llaia doctor` 自检对照。
- 已知边界保持诚实：低权账户挡写不挡读（敏感文件 ACL 需单独收紧）；delegate 无审批性质不变。

## 明确不做

- 不加任何 Windows API crate；不动 terminal/MCP spawn 通路（scrub_child_env / infra-guard 均保持原样）。
- 不做代码内 per-command 降权包装（B/C 弃选理由如上，留档本文件即可）。
- doctor 探测不做「Administrators 组 deny-only」细节识别（UAC filtered token 的字符串判定脆弱，超出自检定位）。

## 验收

- `cargo fmt --all --check`、`cargo clippy --all-targets -- -D warnings`、`cargo test`（清代理环境变量）全绿。
- 本机 `cargo run -- doctor` 输出 security 段：medium integrity + 账户名正确。
- docs/plan.md P9 Phase 3 勾选 + ADR-0033 Phase 3 回填交付日期。
