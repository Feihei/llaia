# P9 Phase 2 剩余四项实现计划（防泄露组合刀收尾）

- 日期：2026-10-06
- 关联：[ADR-0033](../adr/0033-security-model.md)、[plan.md](../plan.md) P9、[Phase 1 + env 剔除计划](2026-10-05-p9-snapshot-and-env-scrub.md)（已交付）
- 范围：Phase 2 剩余四项，按 plan.md 顺序：基础设施文件只读守卫 → web_fetch 出站闸门 → terminal 网络命令风险标记 → 拒绝话术两原则。

## 1. 基础设施文件只读守卫（L3/A1+A2）

**守卫对象**：config_dir 根的 `config.toml` / `.env` / `mcp.toml` / `trusted_dirs.json`（A1；`.env` 是 ADR §1 资产表 A1 成员，plan.md 四文件清单未列全，补上）+ 家目录 `sessions.db`（A2，含 `-wal`/`-shm` 侧车）。**cron.toml 刻意不守卫**：agent 经 `cron_task` 工具有特许管理通路，文件层硬拒只是把同一动作挪进更绕的形态。

**语义**：命中即 `[infra-guard]` 拒，**execute 与 execute_approved 同拒**（判据 2：A1 直接拒，不给人审被哄骗的机会）。现状缺口在审批层——config.toml/.env 界外走审批，`/ok` 后 `execute_approved` 跳过范围检查即可写入；terminal 路径提取同理。守卫位置在工具执行层（复用 Phase 1 的 `snapshot_root` 硬拒机制）。

**结构**：`SnapshotCtx` 更名 **`GuardCtx`**（职责扩为 A0/A1/A2 资产守卫），字段加 `config_dir`，新增 `blocks_infra_write(resolved)`（path_guard 提供 `infra_readonly_target` 纯函数）；`store` 改 `Option`（main 且 snapshot_enabled 才有——子 agent 不做快照挂钩，但**守卫上下文全 agent 注入**，堵 delegate 拿子 agent 工具写主家 sessions.db 的口）。快照根守卫随 `store.is_none()`（总开关关）一起失活。

## 2. web_fetch 出站闸门（L4，两道分离）

**SSRF 校验无条件常开**（`web.rs` 执行层，execute 与 execute_approved 同过）：scheme 仅 http/https；host 为 IP 字面量直接判定，域名先 DNS 解析再**逐 IP 复验**（防 rebinding 的第一步；与 reqwest 自行解析的 TOCTOU 残窗留档接受）。封锁集：环回 / 私网三段 / 链路本地（含云元数据 169.254.169.254）/ 未指定地址 / IPv6 unique-local / IPv4-mapped IPv6 解包复查。

**域名闸门只收紧非交互频道**（`is_interactive_channel` 反集：cron:*/delegate/mail）：
- 允许清单 `[tools.web_fetch].allowed_domains`（默认空 = **fail-closed 全拒**）；匹配 = 精确或子域后缀，大小写不敏感。
- 判定点两处：approval 层（`approval_decision` 前置，delegate/yolo 早退**之前**——政策边界不吃 profile 豁免）→ 非交互未列域名直接 Denied；执行层 `execute` 复查（堵 yolo+cron 等组合漏网）。交互频道复查 allowed ∪ approved。
- **交互频道首访审批**：未列域名（且不在已批准集）→ `NeedsApproval`；批准走既有 `execute_approved` 通路，成功后 host 写入内存集 + 持久化 `<config_dir>/web_domains.json`（`WebFetchGate` 持有，trusted_store 同款读写；每 agent 各建一份 gate 实例，并发追加 benign）。
- yolo：交互频道域名审批豁免（yolo 语义），非交互 fail-closed 不豁免（政策非审批）。SSRF 两档都不豁免。

## 3. terminal 网络命令风险标记（L4 留痕，不拦截）

`path_guard::NETWORK_COMMANDS`（curl/wget/nc/ncat/netcat/ssh/scp/sftp/rsync/socat/telnet/ftp + powershell iwr/Invoke-WebRequest/Invoke-RestMethod）+ `network_command_hit(command)`（复用 `destructive_targets` 同款分段/环境变量前缀跳过）。runner 在**既有审计写入点**给 terminal 命令附 `reason=network=<prog>` 标记。顺手收口既有缺口：`resolve_approval` 的 `/ok` 批准执行路径此前**完全不过 audit.log**（P3-a「记录所有 requires_confirm 调用」的漏网），补一条。

## 4. 拒绝话术两原则（L5 话术）

`path_guard::HARD_BOUNDARY_NOTICE` 常量（"This is a hard policy boundary; do not attempt to work around it."），追加到：validate_path 范围拒绝、危险黑名单命中、shell 包装拒绝、approval 非交互 Denied reason。不含任何救济路径（不说「可以让用户 /ok」）；审批**提示**文案（NeedsApproval 的 `/ok` 指引）不是拒绝，保持不变。
