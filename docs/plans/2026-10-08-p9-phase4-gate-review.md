- 日期：2026-10-08

## 方法

判据 3（兜底检验）：「它拦下来的东西，别的层有没有兜底？」有兜底 → 删掉或降级；没有兜底 → 允许存在。Phase 1（快照）+ Phase 2（infra-guard / env scrub / web_fetch 闸）+ Phase 3（T2 部署手册 + doctor 自检）落地后，L1/L2/L3/L4 全部就位——本复审是这套矩阵首次对全部既有闸门做完整性验收。

## T3 复审（第一候选，fork 定案）

**判据 3 检验**：

- A0（人格文件）/ A1（凭据）/ A2（会话史）的内联载荷写入：已由 L1 快照 + infra readonly guard + Delete Guard **兜住**——这部分不再依赖 T3。
- 残余缺口：**A3 界外（workspace 外、非快照非受信）经内联载荷的写/删**。默认部署（未上 T2 专用账户）对这一格无 OS 层兜底 → 判据 3 严格输出：**没有兜底 → 允许存在**。
- L2 部署手册已交付（Phase 3）：部署 T2 后该残余被 OS 权限接管，摘除即有现实前提。

**fork 选项**：

- **A · 保留默认 + 叙事重定位**（选定）：`interpret_inline` 默认 `approval` 不动；文档承认 T3 是「无意识操作强制人审点 + 审计信号」，**非安全边界**（delegate / script 文件绕行既有留档）；写明部署 T2 后 `interpret_inline = "off"` 的摘除路径。
- B · 新增 `"audit"` 档设为默认：零摩擦且诚实，但默认部署用户失去唯一覆盖无兜底格子的人审点——为一致性与 L2 灰度冲突，弃。
- C · 删除 T3：伪边界彻底摘除，代价同 B 且更大，弃。

**结论**：闸门准入看判据，不凑减法 KPI。复审输出 = **零删除、零代码降级**，但完成两类叙事重定位（T3 定性、黑名单降为提示层）+ 一条 T2→摘除 T3 的迁移路径——这正是「文档上承认防不住」优于「伪边界」的落地形态。
